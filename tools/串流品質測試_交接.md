# 串流品質測試：交接 prompt

把下面「---」之間的內容整段貼到直播輔助腳本那個專案的新對話裡。

---

我想在我的直播輔助腳本的「開播」分頁加一個 **「串流品質測試」** 功能（腳本有 PK／直播間／開播／主播分析／關於我 這幾個分頁）。按一下就開始錄一段串流，直接在瀏覽器裡分析並顯示報告，不用另外安裝 Python 或 ffmpeg。

## 背景

- 我在另一個 repo 用 Python + ffprobe 做過同樣的分析，可以參考：GitHub `gaspard225/2026-yin-wei-you-ni-`，分支 `claude/happy-davinci-gcdf67`，檔案 `tools/stream_probe.py`。指標、判讀規則（`verdict()`）、報告版面都照它做，只是改成在瀏覽器裡用 JS 跑。
- 「開播」分頁現在已經有「實測碼率（6s）」，代表腳本已經能在瀏覽器裡拿到串流資料。請先找到這段程式碼，用同樣的方式抓資料（fetch 或 GM_xmlhttpRequest 串流讀取，看現有寫法）。

## 做法

- 讀 FLV 串流，自己解析 FLV tag：tag 類型（8 = 音訊、9 = 視訊）、資料大小、時間戳，以及視訊 tag 第一個 byte 的 frame type（1 = 關鍵幀）。不用解碼就能算出下面所有指標。
- 解析度從 AVC sequence header（SPS）取得，或直接用分頁裡現有的資訊。
- 截圖：從頁面上正在播放的 video 元素用 canvas 擷取，並標註正在播放的是哪個畫質。
- HLS 支援可以之後再做，第一版只做 FLV。

## 要算的指標

- 每秒視訊碼率，以及 5 秒移動平均的最低 / P10 / 中位數 / P90 / 最高
- 碼率偏低時間占比：5 秒平均低於中位數 70% 的時間比例，並列出是哪幾段
- 實際 FPS、關鍵幀間隔、I 幀與非 I 幀的平均大小
- 時間戳斷層：相鄰視訊 tag 間隔超過正常幀間隔 3 倍就算一次，統計次數和總秒數（代表掉幀或卡頓）
- 每像素位元 = 碼率 ÷（寬 × 高 × FPS）
- 錄製實際花的時間對比拿到的內容長度，用來判斷下載是否卡住
- 判讀文字，規則照 `stream_probe.py` 的 `verdict()`

## 介面

- 「開播」分頁加一個「串流品質測試」區塊，可以選：
  - 畫質，預設藍光 FLV
  - 錄製秒數：30 / 60 / 180 / 300，預設 180
  - 測試名稱，例如「無特效」「有特效」
- 錄製中顯示進度和即時碼率曲線，可以中途停止
- 完成後顯示報告：碼率曲線（SVG）、指標表、判讀、截圖
- 同時記下當下的開播資訊：主播名稱、手機型號、os_version、宣告碼率、max_bitrate / min_bitrate / default_bitrate、是否經 CDN 轉碼（encoder=Lavf…、transcodeid）、節點
- 每次結果都存下來（GM_setValue 或 localStorage），可以挑兩次並排比較。例如同一個主播「無特效 vs 有特效」，或兩個主播同時段比較
- 可以匯出 HTML 報告和 CSV

## 之前調查得到的注意事項

- 「串流連結」裡每個畫質標示的 Mbps（例如「藍光 3.4 Mbps」）**不是實際碼率**。有主播 max_bitrate 只有 2166，藍光卻標 3.4 Mbps。比較一律用實測值。
- 藍光有時是主播的原始流，有時是 CDN 轉碼過的（encoder=Lavf…、有 transcodeid）。報告要清楚標示，這兩種不能直接比。
- 碼率設定（max / min / default_bitrate）每個主播、每天都可能不同，報告要一起記錄。
- 實測碼率差不多時，清晰度主要受美顏特效、打光、對焦影響。例如同一位主播開了「淡顏天花板」特效後明顯變糊，碼率卻差不多。所以截圖和並排比較很重要。
